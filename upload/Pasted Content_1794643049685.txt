## 1. CONSTRAINTS (all free tier, non-negotiable)
- No paid services. ## 4. FEATURE SPEC

### 4.1 Broker auto-sync via Expert Advisor (MT4/MT5 webhook)
**Setup wizard at /settings/broker-sync** (step by step, FR/EN, with screenshots placeholders):
1. Create a connection: choose the target Account (or create one), platform MT4 or MT5, label. The raw token is displayed ONCE with copy buttons for the endpoint URL and the token. Regenerate/rotate and revoke actions
2. Download the EA file (served from `/public/ea/TradeJournalSync.mq5` and `.mq4`) and install: copy into `MQL5/Experts` (or `MQL4/Experts`), compile in MetaEditor, attach to ONE chart
3. **Allow the URL**: Tools > Options > Expert Advisors > "Allow WebRequest for listed URL", add the app's base URL (HTTPS required). Explain that the EA cannot send anything until this is done
4. "Waiting for first heartbeat" live status with a connection test button; show detected broker server, login, EA version, last heartbeat, last event, and a status badge (ACTIVE / STALE / MISMATCH / REVOKED)
- Honest requirements displayed in the UI: MetaTrader must be running with the EA attached (a VPS is recommended for continuous sync); some brokers or prop firms disable EAs or WebRequest, in which case the file import (4.2) is the fallback; the sync is one-way (broker -> app) and read-only (the EA NEVER places, modifies or closes orders)

**Endpoints** (Node runtime, `maxDuration` set low, body limit ~1 MB, max 200 events per request):
- `POST /api/ingest/mt` with `Authorization: Bearer <token>`: validates with Zod, looks up the connection by token hash, applies rate limits, processes events, returns per-event results (ACCEPTED | DUPLICATE | REJECTED + reason)
- `GET /api/ingest/mt/ping`: validates the token and returns server time, binding status and remote config (e.g. `historyBackfillFrom`, heartbeat interval) so the user changes settings from the web instead of recompiling
- Reject requests with a timestamp skew greater than 10 minutes (replay protection). First heartbeat binds the connection to (brokerServer, brokerLogin); later mismatches set MISMATCH and reject events (prevents mixing two MT accounts into one journal). A token for user A can never write to user B's accounts, even with a guessed accountId (the accountId comes from the connection, never from the payload)

**Payload contract** (`schemaVersion: 1`; ALL numeric values are strings to preserve decimals; times are Unix seconds in broker server time PLUS `serverGmtOffsetSeconds` so the server converts to UTC reliably):
```json
{
  "schemaVersion": 1, "platform": "MT5", "eaVersion": "1.0.0",
  "server": "BrokerName-Live01", "login": "12345678", "currency": "USD", "leverage": "500",
  "serverGmtOffsetSeconds": 7200, "sentAt": 1735732800,
  "events": [{
    "eventId": "MT5:BrokerName-Live01:12345678:DEAL:987654321",
    "type": "POSITION_CLOSED",
    "symbol": "XAUUSDm", "symbolSpec": {"digits": "2", "point": "0.01", "tickSize": "0.01", "tickValue": "1", "contractSize": "100"},
    "positionId": "555", "ticket": "987654321", "direction": "LONG", "volume": "0.10",
    "openTime": 1735700000, "openPrice": "2650.50", "closeTime": 1735730000, "closePrice": "2655.80",
    "stopLoss": "2645.00", "takeProfit": "2660.00", "commission": "-0.70", "swap": "0.00", "fees": "0", "profit": "53.00",
    "magic": "0", "comment": "", "mfePrice": "2656.40", "maePrice": "2649.10", "mfeMaeComplete": true
  }]
}
```
Event types: HEARTBEAT (balance, equity, margin, open positions count), POSITION_OPENED, POSITION_MODIFIED (SL/TP/volume changes), POSITION_PARTIAL_CLOSE, POSITION_CLOSED, ORDER_PLACED / ORDER_CANCELLED (pending orders, optional), BALANCE_OPERATION (deposit/withdrawal/credit => CashTransaction), HISTORY_BATCH (backfill of closed positions/deals since `historyBackfillFrom`, paged by 100).

**Server-side processing (pure, idempotent, unit-tested in `/src/lib/sync/`)**:
- Dedupe by (userId, eventId) in SyncEventLog; retries and out-of-order delivery must never create duplicates or regress a CLOSED trade back to OPEN. Derive trade state from the set of events, ordered by event time, not by arrival
- Map broker symbols to Instruments: apply SymbolMapping, then normalization (strip common suffixes/prefixes such as m, .pro, ., #, _i, micro; alias GOLD -> XAUUSD), else create a pending mapping the user confirms in the UI. Pre-fill a new Instrument from the EA-provided `symbolSpec` (digits, point, tick size/value, contract size), then let the user override pip size (XAUUSD pip convention stays configurable as in v1)
- MT5: a trade = a position (`positionId`); in/out/in-out/out-by deals map to `TradeExecution` rows (ENTRY, ADD, PARTIAL_EXIT, FINAL_EXIT); hedging and netting accounts both handled (netting reversals close one trade and open another). MT4: a trade = an order ticket; a partial close creates a new ticket whose comment references the original (`from #123` / `to #456`) so the chain is stitched into one trade with executions
- Aggregates (average entry/exit, pips, points, R using the INITIAL stop loss, planned/realized RR, net P&L with commission/swap/fees, pnlSource = BROKER for synced P&L) computed with the v1 engine; broker P&L overrides estimates. SL/TP changes create TradeModification rows; the first SL/TP seen becomes `initialStopLoss`/`initialTakeProfit` unless the user already set them
- MFE/MAE: the EA tracks max favorable/adverse price while a position is open; if the EA was offline during part of the trade, `mfeMaeComplete = false` and the UI/what-if simulator flag it
- New synced trades get: `source = EA_SYNC`, `needsDetails = true`, strategy from MagicNumberMapping if any, reviewStatus NOT_REVIEWED, session auto-detected; they appear in /review (v2), in a dashboard widget "N synced trades to complete" and in the offline cache
- BALANCE_OPERATION => CashTransaction (type by sign, dedupe via externalId). HEARTBEAT => update connection status and AccountEquitySnapshot
- STALE detection: no heartbeat for 30+ minutes on a weekday market session => status STALE and a SYNC_STALE notification (evaluated on app open and in the daily cron; do not alert on weekends)
- After processing a new or closed trade, trigger the existing v2 side effects (prop alerts, news linking, market context queue, stats cache revalidation) and the reconciliation matcher (4.3)

**EA source code (`/ea/MT5/TradeJournalSync.mq5`, `/ea/MT4/TradeJournalSync.mq4`)**:
- Inputs: ApiUrl, ApiToken, HeartbeatMinutes (default 5), SendHistoryFromDate, DebugLog. No trading functions whatsoever
- MT5: `OnTradeTransaction` (TRADE_TRANSACTION_DEAL_ADD, ORDER, POSITION events) plus an `OnTimer` heartbeat and a missed-event reconciliation pass using `HistorySelect`; MT4: scan the order pool/history on a timer and diff against a stored state
- Manual JSON string building with proper escaping; `WebRequest` with timeout and `Authorization` + `Content-Type` headers; persistent outbox in files (`FILE_COMMON`) so events survive terminal restarts or network failures; exponential backoff; log clearly when WebRequest is not whitelisted (error 4060/4014 hints)
- Convert nothing to UTC in the EA: send server time and the GMT offset
- IMPORTANT: you cannot compile or run MQL in this environment. Write the EA carefully, add a header comment stating it must be compiled in MetaEditor and tested on a DEMO account first, and provide `scripts/simulate-ea.ts` which POSTs realistic payloads (open, modify SL, partial close, close, deposit, duplicate and out-of-order events, a mismatched login) to the ingest endpoint for automated tests and manual testing. Mark in the README that the EAs are unverified until the user compiles and tests them

### 4.3 Reconciliation (manual vs synced/imported duplicates)
- **Matcher** (pure, unit-tested in `/src/lib/reconciliation/`): for each broker-sourced trade, find manual trades in the same account that are probably the same: same instrument (after mapping) and direction required; score by entry-time proximity (<= 2 min strong, <= 15 min medium, same day weak when the manual trade only has a date), entry price within a configurable tolerance in pips (stricter for forex, wider for XAUUSD), lots equal within epsilon, exit price/time proximity when closed. Exact externalId match = certain. Thresholds configurable in settings. Output a score 0-1 with human-readable reasons. Run after every EA batch/file import and on demand
- **/reconciliation** page: queue of candidate pairs with side-by-side diff (manual vs broker), score and reasons; per-field choice with smart defaults, bulk "merge all high-confidence (>= 0.9, exactly one candidate)", "Not a duplicate", "Keep separate", filters by account/period, badge count in the nav and a RECONCILIATION_PENDING notification
- **Merge rules**: broker-sourced data wins for externalId, positionId, prices, times, lots, executions, commission, swap, fees, net P&L, final SL/TP; user-entered data wins for strategy, tags, notes, emotions, ratings, checklist, screenshots, planned initialStopLoss/TakeProfit when the user entered them, TradeReview, comments, share links, event links, template. The merge runs in one DB transaction: re-point ALL child rows (screenshots, tags, executions, reviews, comments, event links, market context, share links, modifications) to the surviving trade, delete the duplicate, recompute derived values with the v1 engine, and write a TradeMergeLog snapshot enabling **undo within 30 days**
- Optional per-connection `autoMergeEnabled` (default OFF): auto-merge only when score >= 0.9 and exactly one candidate; every auto-merge is logged and undoable
- Offline outbox (v2) interplay: a trade created offline and synced later may match a broker trade; matcher runs after the outbox sync completes
